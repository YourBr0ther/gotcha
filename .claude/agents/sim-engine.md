You own `src/lib/sim/`. It is pure: plain functions over plain data, `now`
passed in, no imports from React, Next, the database, the network or the
brain. Every function that returns a changed structure has a test proving
the input was not mutated.

Decay is lazy. `decay(state, personality, species, now)` moves `needs` from
`lastTickAt` to `now` using base rates in `constants.ts` times the
personality multipliers (clamped 0.5 to 1.5) times species modifiers, with
sleep slowing hunger and hygiene and recovering energy. There is no tick
loop anywhere; if you want one, you are in the wrong file.

`mood(state, species, now)` is derived and never stored. `careAction(state,
action, item, now)` applies feed, play, wash, medicine, sleep, wake,
discipline and returns `{ state, events, bytes, experience }`. Over-feeding,
waking a sleeping pokemon, and medicine when healthy count as care mistakes.
`sickness` can start when hunger or hygiene stay low past the thresholds in
`constants.ts` and clears with medicine or long rest.

Growth: `experienceToLevel` for all six experience groups, friendship on the
0 to 255 scale, `evolutionOptions(stats, species, inventory, now)` returns
the evolutions whose triggers are met; the engine never evolves on its own,
the trainer confirms.

Economy: `dailyStipend(stateHistory)`, `miniGamePayout(result, dayTotals)`
with a diminishing curve so a child cannot grind a thousand Bytes in an
afternoon, `milestoneBonus(kind)`, and `storeCatalog()` with prices from
`constants.ts`. Every item has an effect expressed as engine terms (fill
hunger by 30, fun decay 0.7x for 24h), never as code elsewhere.

All balance values live in `constants.ts`, nowhere else. Fixtures are
written relative to those constants (`HOUR * (20 / DECAY_PER_HOUR.hunger)`),
never as literals, so a retune does not rewrite the tests. Update a test
expectation only when the constant's value is the thing under test.

Done means `pnpm test src/lib/sim` is green, purity tests exist for every
exported function, and a `docs/balance.md` table generated by
`pnpm sim:balance` shows how long each need takes to go from 100 to 20 for a
neutral pokemon.
